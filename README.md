# copc-tiles-validate

A lightweight **structural** validator for general 3D Tiles assets, including datasets generated by COPC Adapter and other tools. It does not require COPC.

This project repurposes the standalone [FrilLab/copc-tiles](https://github.com/FrilLab/copc-tiles) repository. The original Tiles generation engine has moved to [COPC Adapter / packages/tiles](https://github.com/mors119/copc-adapter/tree/main/packages/tiles). The prior standalone code remains in Git history and historic issues.

> **Status:** Unreleased development candidate. This tool does **not** certify full 3D Tiles or glTF conformance. Retain the official [CesiumGS 3D Tiles Validator](https://github.com/CesiumGS/3d-tiles-validator) and [Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator) as independent release gates.

## Goals

- Source-neutral validation of general 3D Tiles, not COPC-specific.
- Node.js 22.12+, 24, and 26, without native add-ons.
- Zero runtime dependencies on COPC Adapter, Cesium, 3d-tiles-tools, or 3d-tiles-validator.
- Machine-readable issue reports for CLI and CI.
- Bounded reads and traversal of local resources.

## Installation and usage

After the new package is published:

```bash
npx @frillab/copc-tiles-validate ./output/tileset.json
npx @frillab/copc-tiles-validate ./output --json
```

From this checkout:

```bash
npm install
npm run verify
node src/cli.js ./output/tileset.json --json
```

Library API:

```js
import { validateTileset } from "@frillab/copc-tiles-validate";

const report = await validateTileset("./output/tileset.json", {
  checkContent: true,
  maxTiles: 100000,
  maxDepth: 128,
  maxJsonBytes: 8 * 1024 * 1024,
  maxFileBytes: 2 * 1024 * 1024 * 1024,
  maxResources: 100000,
  maxIssues: 500,
});

console.log(report.valid, report.conformance, report.issues);
```

The result has `valid`, `conformance: "partial"`, `issues` (with `severity`, `code`, `path`, `message`), and `stats` fields. CLI exit code: **0** if no *detected* errors, **1** if errors were found, **2** for unsupported arguments or runtime argument failures. Warnings do not change the exit code.

## Implemented checks

- Tileset JSON 1.0 / 1.1: asset, geometric error, root, explicit tile traversal, bounding volumes, transforms, refine and content URI fields.
- Local resource references: missing files, external tileset JSON, cyclic references, directory confinement, percent-encoded traversal and symlink escape.
- GLB 2.0: header, chunk bounds, JSON asset version, embedded buffer length.
- Implicit tiling: subtree configuration, URI template variables, *root* binary subtree header/chunk layout/buffer views/availability objects.
- Configurable limits: tile count, traversal depth, JSON bytes, resource count, file bytes and diagnostic count.

## Known limitations

This package is intentionally **structural and partial**:

- No full glTF/accessor/mesh/extension/metadata semantic conformance checks.
- Only the root implicit subtree is checked; deeper subtrees and availability bit counts are not fully verified.
- No 3TZ / .3dtiles package archive parsing yet.
- Legacy B3DM, I3DM, PNTS, CMPT, standalone .gltf, and custom formats are not fully checked; a warning is emitted.
- Remote, signed, query-bearing or data URIs are not fetched.
- All referenced local resources must reside inside the initial tileset directory. This is stricter than some valid deployment layouts.
- `valid: true` means *no errors found by the implemented checks*, not official standards certification.

Run official validators separately for release and standards conformance. See [issue #21](https://github.com/FrilLab/copc-tiles/issues/21) for migration and acceptance criteria.
